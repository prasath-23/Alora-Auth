# Alora Auth (Go) — Architecture

Production architecture for the **alora-auth** Identity Provider, rewritten from Node/Fastify to
Go/Gin. This document is the architectural contract; **`../MIGRATION_SPEC.md`** holds the exhaustive,
byte-level behavioral + security invariants and the endpoint inventory. Where this doc summarizes,
the spec governs.

> ## ⚠ BUILD STATUS — this document is the TARGET design, not current reality
> Sections 3, 4 (perimeter/middleware) and 6 describe the intended system in the present
> tense. As of the last construct audit, only the foundation is implemented:
>
> **Built & tested:** `internal/config`, `internal/crypto/{tokens,pkce,password,jwtkeys}`,
> `internal/platform/{logger,database}`, `internal/mailer`, 3 migrations, 13 query files
> (+ generated sqlc). **Empty / not yet written:** `cmd/api`, `internal/platform/{httpx,audit,jobs}`,

> Gin is not yet imported. There is **no parity test suite** — current tests cover the pure
> packages only. Treat every CORS / rate-limit / cookie / error-envelope / audit claim below
> as *specified*, not *shipped*.

- **Language/Runtime:** Go 1.26
- **HTTP:** Gin (`github.com/gin-gonic/gin`)
- **DB:** PostgreSQL via `pgx/v5` + `pgxpool`; type-safe queries generated by **sqlc**
- **JWT:** `github.com/lestrrat-go/jwx/v2` (RS256)
- **Password hashing:** `github.com/alexedwards/argon2id` (argon2id)
- **Logging:** stdlib `log/slog` with a redaction handler

## 1. Principles

1. **Package-by-feature, not by layer.** Each bounded context (`auth`, `session`, `oauth`,
   `invitation`, `reset`, `admin`) owns its handler + service + repo + DTOs. Cross-cutting
   machinery lives under `internal/platform`. This keeps a feature's blast radius local.
2. **Dependency direction points inward and downward.** `handler → service → repo → sqlc`.
   Handlers never touch the DB pool; services never touch `*gin.Context`; the sqlc layer never
   imports a feature package. No import cycles.
3. **Thin handlers.** A handler binds/validates input, calls one service method, maps the result
   to an HTTP envelope. All branching, transactions, and security decisions live in the service.
4. **The DTO/persistence boundary is absolute.** Request/response structs (with `binding:` and
   `json:` tags) live in each feature's `dto.go`. They are **never** the sqlc-generated row structs.
   sqlc rows never leak past the repo; services translate.
5. **Fail closed.** Config validation, CORS, authorization, and token verification all default to
   *deny* on error or ambiguity.
6. **Everything security-critical is compile-checked or test-pinned.** SQL is validated by sqlc at
   build time; behavior is pinned by the ported parity test suite.

## 3. Request lifecycle (middleware order is semantic)

```
request-id (uuid)
  → recovery + error handler          (panics → 500 envelope; never leak internals)
  → security headers                  (CSP all 'none', HSTS 1y preload, COEP/COOP/CORP, no-referrer)
  → CORS                              (dynamic, DB-backed, fail-closed; must run after DB is up)
  → cookie parse/verify               (HMAC-signed via COOKIE_SECRET)
  → rate limit                        (per-IP token bucket; skippable in tests)
  → under-pressure                    (heap/RSS guards; 503 when overloaded)
  → [route]
       public/auth routes: no auth
       admin routes: authenticate → requireFreshPermissions → route guard (admin|feature)
```

**No CSRF middleware.** Defense is structural: the refresh cookie is `SameSite=Lax` and every
`/admin/*` route is Bearer-authenticated (a cross-site form cannot forge an `Authorization` header).

## 4. Security architecture

> The user requirement is *zero known vulnerabilities*. Every control below maps to an explicit
> invariant in `MIGRATION_SPEC.md §2` and a threat in §15 of this doc.

### Authentication (JWT)
- **RS256 only.** The verifier pins an algorithm allowlist and resolves the key by `kid`. Tokens
  with `alg:none`/`HS256` or a missing/unknown `kid` are rejected → **alg-confusion is impossible.**
- Keys are loaded **once** at startup (`jwtkeys.Init`) from env PEM; JWKS is served publicly with a
  5-minute cache. Required claims `[sub,exp,iat,iss]`, 5s clock skew, audience enforced only when set.

### Session & refresh-token rotation (the crown jewels)
- Refresh tokens are opaque (hex), stored only as `sha256` hex. Rotation runs in a **pgx transaction**
  with `SELECT … WHERE refresh_token_hash=$1 FOR UPDATE` (no `revoked_at` filter — must see revoked rows).
- **Family rotation:** each login opens a `family_id`; each refresh increments `generation`, links
  `prev_token_hash`/`replaced_by_id`, and revokes its predecessor.
- **Reuse detection:** replay of a spent token outside the 30s grace window **burns the whole family**
  (`UPDATE … WHERE family_id=$1 AND revoked_at IS NULL`) and returns 401. The nuke is **committed
  before returning** (fixing the latent Prisma-`$transaction`-rollback bug in the Node original — Decision D1).
- **Grace race:** a benign concurrent rotation returns **409** (keep cookie, no family burn), never
  collapsing into a 401. Two detection paths guard the boundary.

### Authorization (RBAC) & multi-tenant isolation
- **Precedence:** `is_global_admin` > any role map **value** == `"Admin"` > group feature membership.
  `requireFeature` verifies the group's *own* `client_id` matches the caller's tenant.
- **Freshness:** `requireFreshPermissions` does one DB read per request and 401s unless the user is
  active, not soft-deleted, and the token's `pv` equals the DB `permissions_version`. Revoking access
  is instant via an **atomic** `SET permissions_version = permissions_version + 1`.
- **Tenant isolation is enforced twice:**
  1. *Application:* every tenant-scoped query filters by `client_id = caller.clientId` — never a
     body/param-supplied client id.
  2. *Database:* composite foreign keys `(user_id, client_id) → tbl_users(id, client_id)` on
     sessions, permissions, and group memberships make a cross-tenant row physically unrepresentable.

### Crypto primitives
- **Passwords:** argon2id, `m=19456 KiB, t=2, p=1, salt=16B, key=32B`. Verify swallows all errors →
  `false` (never 500). Max length 512 UTF-16 code units. Unknown-user login path still runs a verify
  against a startup `DUMMY_HASH` → **constant-time anti-enumeration.**
- **Opaque tokens:** refresh = `rand(32B)→hex`; auth codes, reset tokens, OAuth state/nonce =
  `rand→base64url` (unpadded). At rest = `sha256` lowercase hex.
- **PKCE:** S256 only; `base64url(sha256(verifier))` compared with `subtle.ConstantTimeCompare`.
- Single-use redemptions (auth code, invite acceptance) are **single atomic `UPDATE … WHERE <guard>
  RETURNING`** statements — no check-then-act race.

### Cookies
- `alora_rt` (refresh): HttpOnly, `Secure=isProd`, `SameSite=Lax`, `Path=/`, `Domain=COOKIE_DOMAIN`.
- `alora_at` (access): **HttpOnly=false** (JS reads the Bearer), MaxAge 900.
- `alora_oauth_state`: HMAC-signed, HttpOnly, 10-min TTL.
- **No `__Host-` prefix** — the explicit `Domain` attribute is required for `*.alora.io` SSO. Clear
  operations replay Path/Secure/SameSite/Domain exactly.

### Perimeter
- **CORS:** fail-closed. No origin/localhost allowed; `*.alora.test` only in non-prod; otherwise the
  origin host must match a `tbl_clients` row with a verified domain and active tenant. 60s per-origin
  cache (thread-safe). DB error → deny.
- **Rate limiting:** per-IP token bucket with per-route overrides (authorize 10, token 20, refresh 30…).
  `SetTrustedProxies` is an explicit env allowlist — Gin's trust-all default would let clients spoof IPs.
- **Security headers:** strict CSP, HSTS w/ preload, COEP/COOP/CORP, no-referrer.
- **Body limit:** 64 KiB.

### Input validation
- `json.Decoder.DisallowUnknownFields()` → unknown fields are **rejected (400)**, not silently
  dropped (Fastify's `additionalProperties:false`). Services manually enforce `uniqueItems`,
  non-empty PATCH bodies, and slice de-dup, which the binding validator does not.

### Secrets & audit
- **Fail-fast config:** required env asserted at boot; prod placeholder secrets
  (`change-this`,`your-`,`placeholder`,`TODO`,`CHANGEME`) rejected; `COOKIE_SECRET ≥ 32 bytes`.
- **Log redaction is a security control:** auth/cookie/set-cookie headers and secret body fields are
  redacted; pgx query logging is OFF (queries carry hashed tokens).
- **Audit** is append-only, and enforced rather than assumed: the application role holds `INSERT`
  only, and the actor foreign key is `ON DELETE RESTRICT` so a user with history cannot be deleted.
  Both are needed — a referential action runs as the referencing table's owner, so `SET NULL` there
  would erase the actor from existing rows no matter what is revoked. Written
  fire-and-forget on `context.Background()` so it can neither block nor fail a request.

## 5. Data layer

- **pgx/v5 + pgxpool.** One pool, injected into repos. Repos wrap `*sqlc.Queries` + `*pgxpool.Pool`
  and expose `WithTx(tx)` for transactional flows (rotation, invite acceptance).
- **sqlc** generates one shared `Querier` from `../alora-auth-db/api`, whose every statement is a
  `CALL stp_…` or a `SELECT … FROM udf_…`. There is no SQL statement in this repository, so a
  procedure-signature change is a compile error here rather than a runtime failure.
  `jsonb → json.RawMessage`. All id columns are `TEXT` (→ Go `string`) to match the schema exactly.
- **Schema and procedures** live in `../alora-auth-db` — one file per object, applied by
  its idempotent `build.sql`, with run-once changes in `Migrations/`. Deliberate improvements over the Prisma
  original (safe for a no-data rewrite): DB-side `gen_random_uuid()` id defaults, and **`timestamptz`
  everywhere** (the Prisma schema used `timestamp without time zone`, an expiry-correctness hazard —
  all `expires_at < now()` math now shares one UTC clock).
- **DB-enforced invariants Prisma could not express:** composite tenant-isolation FKs, the
  `DEFERRABLE INITIALLY DEFERRED` audit-actor FK, and soft-delete-aware partial unique indexes on
  `lower(email)`, `lower(domain)` (verified only), and `lower(name)` per tenant.
- **Time/typing landmines** (enforced in review): check `pgtype.*.Valid`, never zero-values; Prisma
  `Int` is `int32`; the `IdpProvider[]` enum-array column requires the pgx array codec registered.

## 6. Cross-cutting operations

- **Configuration:** 12-factor env. No config file. `internal/config` is the single validated source.
- **Observability:** structured slog (pretty in dev, JSON in prod); `/health` (liveness),
  `/health/ready` (SELECT 1), `/health/pressure` (heap 500MB / RSS 600MB guards; event-loop delay is
  N/A in Go).
- **Background jobs:** `time.Ticker` goroutines started *after* the listener binds; expire-sessions
  hourly, expire-invitations every 6h; stopped via context cancel on shutdown.
- **Concurrency:** handlers are synchronous. The only goroutines are audit/email (fire-and-forget,
  `context.WithoutCancel` + `recover()`) and the job tickers.
- **Errors:** `≥500 → {error:"Internal Server Error", reqId}` (never leak); `4xx → {error:label,reqId}`;
  `23505 → 409`; validation → 400; `404 → {error:"Not Found"}`.
- **Graceful shutdown:** SIGINT/SIGTERM → stop accepting, drain, cancel jobs, close pool.

## 7. Testing & parity

The 14 Fastify `node:test` suites are the **parity oracle**. Each is ported to a Go `httptest`
integration test running against a real throwaway Postgres (repo fakes would lose `FOR UPDATE` /
`UPDATE…RETURNING` semantics). Parity is declared only when every ported behavior — jwt-security,
refresh rotation/reuse, logout, token, authorize, google, reset, admin-session, all `admin.*`, jwks,
health — passes in Go. Only then is the Fastify backend decommissioned.

---

## 8. Deployment

Single static binary. Env-configured. Runs behind a reverse proxy (set `TRUSTED_PROXIES`).
**Scaling caveat:** the OAuth state store is in-process (Decision D6). It is correct for a single
instance; running multiple replicas requires externalizing it to Redis (the Google callback may land
on a different pod than `/auth/google`). This is flagged, not yet built.

## 9. Threat model → controls

| Threat | Control |
|---|---|
| JWT algorithm confusion | RS256 allowlist + kid resolution; reject none/HS256/unknown-kid |
| Refresh token theft / replay | Family rotation + reuse detection (family burn), `FOR UPDATE` lock, committed nuke |
| Cross-tenant data access | client_id scoping in every query **+** composite FKs at the DB |
| Privilege escalation via stale token | `permissions_version` freshness check per request |
| User/account enumeration | Identical 401s + dummy-hash verify on unknown user |
| Password cracking | argon2id (19456/2/1); hashes never logged/returned |
| Open redirect (OAuth) | redirect_url validated against product.base_url at issue **and** exchange |
| PKCE downgrade / interception | S256 only; constant-time verify |
| CSRF | SameSite=Lax refresh + Bearer-only admin; no ambient-credential mutation |
| CORS bypass | Fail-closed, DB-verified origins; never wildcard with credentials |
| Injection | 100% parameterized via sqlc; no string-built SQL |
| Mass-assignment / unknown fields | DisallowUnknownFields → 400 |
| IP spoofing → rate-limit bypass | Explicit trusted-proxy allowlist |
| Secret leakage in logs | Redaction handler; pgx query logging off |
| Weak/placeholder secrets in prod | Fail-fast startup validation |
| Audit tampering | Append-only table; no update/delete path generated |
